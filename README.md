# work-samples

業務システムと自動化ツールのサンプル集です。すべて実際に動作します。

現場の業務を実際に回してきた経験をもとに、**設定を差し替えるだけで別の業務にも使える**形で作っています。
それぞれのフォルダに、動かし方と設定の書き方を置いています。

---

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/)** — どのサンプルを見ればよいか分からない場合は、こちらからどうぞ。

「見積り後に連絡が途切れて失注する」「電話が鳴りっぱなしで手が止まる」といった**症状から引ける索引**です。14件の悩みごとに、公開データによる裏づけ・何が起きているか・解決の型・該当するデモの場所をまとめています。

各サンプルの技術名ではなく、いま困っていることから探せます。数値の出典と注記はページ末尾にまとめてあります。

## 1. 受付一元化＋進捗自動連絡 — `demos/uketsuke-ichigenka/`

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/demos/uketsuke-ichigenka/)** — インストール不要、その場で操作できます。

電話・Webフォーム・LINE・来店の受付を1つの台帳にまとめ、**工程が進むたびに自動で連絡する**仕組みのデモです。上部のタブで4画面を切り替えられます。索引ページからの主な行き先で、意匠も索引ページと共通です。

| 画面 | 内容 | 直接開くURL |
|---|---|---|
| ① 業務棚卸し | 工程ごとの所要時間×月間件数を一覧にし、自動化できる／半自動化／人がやるべきの3分類に振り分け。時給スライダーで人件費換算 | `#tanaoroshi` |
| ② 受付 | お客さま側の入力フォーム。送信すると自動返信の文面が出ます | `#uketsuke` |
| ③ 管理画面 | 社内側の受付一覧と1件の詳細。「工程を進める」で自動連絡が履歴に1行増えます | `#kanri` |
| ④ 導入後の数字 | 4指標の導入前後と、削減時間・人件費換算 | `#suuji` |

- **緊急語の検出と、判定の根拠の表示** — 本文に緊急語が含まれると緊急と判定し、**判定に使った語をそのまま画面に出します**。判定に使う語の一覧も画面から確認できます。なぜ緊急になったのか説明できない状態を作らないためです
- **自動と担当を分けた対応履歴** — 履歴の各行に「自動」「担当」の別を付け、担当者が動かなくても送られた連絡がどれかを見て分かるようにしています
- **①の時給スライダーは④の人件費換算と連動**します
- **URLのハッシュで画面を直接指定できます** — 上表のとおり `#tanaoroshi` `#uketsuke` `#kanri` `#suuji`。索引ページからは、悩みごとに該当する画面へ直接リンクしています

業種を切り替えると、工務店・リフォーム／歯科医院／自動車整備に変わります。工程名・所要時間・月間件数・受付項目・ステージ名・緊急語が入れ替わりますが、**画面の構造とコードは完全に同じ**です。変えているのはファイル冒頭の `INDUSTRIES` の1オブジェクトだけで、業種を1つ足すと切替ボタンが1つ増えます。

所要時間・件数・導入後の数字は、すべて**デモ用の想定値**です。実在する企業の実績ではありません。受付フォームに入力した内容はどこにも保存・送信されません（localStorage・Cookie・外部通信のいずれも使っていません）。

**React / Tailwind CSS（1ファイル構成・CDN読み込み・ビルド不要）**

## 4. デジタル商品EC — `digital-ec/`

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/html/digital-ec.html)** — インストール不要、その場で操作できます。

## 6. データ収集ツール — `scrape-report/`

指定したページから必要な項目を集め、CSVと集計レポートを書き出します。

**別サイトを収集したい場合、コードは触りません。`config.json` を差し替えるだけです。**

- 取得項目・整形ルールをすべて設定ファイルに記述
- 「3,280円」→ `3280`、「2026年8月11日」→ `2026-08-11` のように表記を統一
- 重複行の除外、取得失敗ページの記録
- **CSVだけでなく集計レポートも同時に出力** — 内訳・分布に加えて、**取得できなかった項目の件数**まで出します

最後の項目が重要です。空欄が急に増えたときは、対象ページの構造が変わった合図になります。

**Python / requests / BeautifulSoup**

## 7. Excel業務の自動化キット — `excel-kit/`

毎月くり返している作業を、設定ファイルを書くだけで自動化します。Excelはそのまま使い続けられます。

| ジョブ | 内容 |
|---|---|
| `reconcile` | 2つの表を突き合わせて、**合わない箇所だけ**を洗い出す |
| `aggregate` | 複数のファイルを1つにまとめて、条件別に集計する |
| `fill` | 決まった書式に流し込んで帳票や文面を作る |

**突合が中心です。** 請求と入金、発注と納品、勤怠と給与。手作業だと見落としが出て、しかも見落としたこと自体に気づけない作業です。

同梱サンプルで実際に検出される内容です。

- **440円の差** … 振込手数料が引かれている
- **50,000円の差** … 一部入金
- **請求のみ2件** … 未入金
- **入金のみ2件** … 請求番号ではなく取引先名で振り込まれている

`inv-2026-0801` と `INV-2026-0801` を同一と見なすなど、キーの表記ゆれも設定で吸収します。突合が失敗する原因のほとんどがここです。

**Python / pandas / openpyxl**

新築・リフォームの**問い合わせ獲得**を目的にした、工務店サイトの全6ページ構成です。

- トップ／施工事例一覧（新築・リフォームで絞り込み）／施工事例の詳細／リフォームのご案内／会社案内／お問い合わせ

## 10. 補助金・助成金マッチング PoC — `demos/hojokin-matching/`

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/demos/hojokin-matching/)** — インストール不要、その場で操作できます。

事業者の情報から、使える可能性のある補助金・助成金を提案する仕組みの試作です。上部のタブで3画面を切り替えられます。

- **事業者情報とマッチング** — 事業形態・業種・従業員数・所在地・設立年・売上規模・取り組み内容を入れると、その場で候補が並び替わります
- **適合度の計算ロジック** — 配点表と、いまの入力での全10件の計算結果を表で確認できます
- **本番実装に向けて** — 制度データの集め方、精度の上げ方、このPoCで割り切っている点

**なぜその制度が該当したのかを画面から追えること**を優先しています。適合度は要件ごとの加点式で、内訳と該当理由（入力値と要件を突き合わせた文）を1件ずつ表示します。

判定は**合致／不一致／要確認**の3値です。入力情報だけでは判定できない要件は不一致に丸めず、**0点のまま「要確認」として出します**。必須要件を外れた制度も画面から消さず、対象外の理由をつけて別枠に残します。候補に出てこない理由が分からない状態を作らないためです。

掲載している制度10件は**すべて架空**です。本番では公募中の制度データを出典URL・取得日時つきで取り込み、判定はルールエンジン、LLMは公募要領からの要件抽出に限定する想定です（判定にLLMを使うと同じ入力で結果が揺れ、根拠を再現できなくなるため）。

**React / Tailwind CSS（デモ）**
