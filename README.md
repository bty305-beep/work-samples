# work-samples

業務システムと自動化ツールのサンプル集です。すべて実際に動作します。

現場の業務を実際に回してきた経験をもとに、**設定を差し替えるだけで別の業務にも使える**形で作っています。
それぞれのフォルダに、動かし方と設定の書き方を置いています。

---

## 1. 業務管理システム — `gyomu-kanri/`

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/html/gyomu-kanri.html)** — インストール不要、その場で操作できます。

複数拠点を持つ会社向けの管理システムです。人材管理・在庫管理・設備点検を、同じ仕組みで扱えます。

- **マルチテナント構成** — 拠点ごとにデータを分けつつ、本部では横断して集計
- **権限管理** — 本部管理者・拠点責任者・現場スタッフで、見える範囲と編集できる範囲が変わります
- 一覧・検索・CSV出力、スマホからの入力を前提にした画面

画面上部の「業務」を切り替えると、同じコードのまま人材管理・在庫管理・設備点検に変わります。変えているのは項目定義だけです。

**React / Supabase / Vercel**

## 2. 予約・受付システム — `yoyaku-system/`

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/html/yoyaku-system.html)** — インストール不要、その場で操作できます。

サロン・飲食店・教室で使える予約システムです。お客さま向けの予約画面と、店舗向けの管理画面があります。

- メニュー → 日付 → 時間 → お名前の4ステップで予約完了
- **重複予約を防止** — 所要時間を考慮して、埋まっている枠は選べません
- 定休日・営業時間を設定から反映
- 管理画面は**時間軸の帯**で、担当（席）ごとの空き状況が一目で分かります
- 来店済み・キャンセル・無断キャンセルの記録、当日の売上集計、CSV出力

業種を切り替えると、サロン・飲食店・教室に変わります。変えているのはメニュー・担当（席）・営業時間・定休日・入力項目だけです。

**React / Supabase / Vercel**

## 3. デジタル商品EC — `digital-ec/`

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/html/digital-ec.html)** — インストール不要、その場で操作できます。

デジタル商品を販売するECサイトです。**配信方法の異なる2種類の商品を、1つの注文管理で扱えます。**

- **ダウンロード商品** — 決済完了と同時にリンクを自動発行。有効期限48時間、3回まで
- **個別対応商品** — 自動配信せず、管理画面に「未対応」として通知
- 注文一覧、売上集計、未対応の絞り込み、CSV出力

有効期限と回数制限はサーバー側で判定する構成のため、リンクを共有されても期限後は開けません。

**React / Next.js / Stripe / Supabase**

## 4. データ収集ツール — `scrape-report/`

指定したページから必要な項目を集め、CSVと集計レポートを書き出します。

**別サイトを収集したい場合、コードは触りません。`config.json` を差し替えるだけです。**

- 取得項目・整形ルールをすべて設定ファイルに記述
- 「3,280円」→ `3280`、「2026年8月11日」→ `2026-08-11` のように表記を統一
- 重複行の除外、取得失敗ページの記録
- **CSVだけでなく集計レポートも同時に出力** — 内訳・分布に加えて、**取得できなかった項目の件数**まで出します

最後の項目が重要です。空欄が急に増えたときは、対象ページの構造が変わった合図になります。

**Python / requests / BeautifulSoup**

## 5. Excel業務の自動化キット — `excel-kit/`

毎月くり返している作業を、設定ファイルを書くだけで自動化します。Excelはそのまま使い続けられます。

| ジョブ | 内容 |
|---|---|
| `reconcile` | 2つの表を突き合わせて、**合わない箇所だけ**を洗い出す |
| `aggregate` | 複数のファイルを1つにまとめて、条件別に集計する |
| `fill` | 決まった書式に流し込んで帳票や文面を作る |

**突合が中心です。** 請求と入金、発注と納品、勤怠と給与。手作業だと見落としが出て、しかも見落としたこと自体に気づけない作業です。

同梱サンプルで実際に検出される内容です。

- **440円の差** … 振込手数料が引かれている
- **50,000円の差** … 一部入金
- **請求のみ2件** … 未入金
- **入金のみ2件** … 請求番号ではなく取引先名で振り込まれている

`inv-2026-0801` と `INV-2026-0801` を同一と見なすなど、キーの表記ゆれも設定で吸収します。突合が失敗する原因のほとんどがここです。

**Python / pandas / openpyxl**

## 6. 工務店コーポレートサイト — `demos/koumuten-site/`

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/demos/koumuten-site/index.html)** — インストール不要、その場で操作できます。

新築・リフォームの**問い合わせ獲得**を目的にした、工務店サイトの全6ページ構成です。

- トップ／施工事例一覧（新築・リフォームで絞り込み）／施工事例の詳細／リフォームのご案内／会社案内／お問い合わせ
- 事例詳細に**費用の内訳と工期**を明示。金額を隠さないことで、予算感の合った問い合わせだけが残ります
- **電話とフォームを常時表示**（PCはヘッダー固定、スマホは画面下固定）
- 対応エリアをファーストビュー直下・フッター・フォームの3箇所に明示。フォームはエリア外をその場で判定
- フォームは必須チェックと入力形式（かな・電話・メール・郵便番号）の検証つき

画面右上の「**設計意図**」を開くと、どこを狙ってこの構成にしたかを画面上で確認できます。

会社名・配色・対応エリア・施工事例はファイル冒頭の設定オブジェクトにまとめてあり、他の工務店にもそのまま転用できます。

**WordPress（オリジナルテーマ）／ React**
