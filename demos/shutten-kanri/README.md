# 出店者管理システム — `demos/shutten-kanri/`

イベントの出店者を管理するウェブアプリのデモです。`index.html` をブラウザで開くだけで動きます（インストール不要）。

**▶ [ブラウザで開く](https://bty305-beep.github.io/work-samples/demos/shutten-kanri/)**

画面上部で「出展者マイページ」と「主催者の管理画面」を切り替えられます。

---

## 【1】出展者マイページ

- **次回出店日と時間**を最上部に大きく表示（搬入開始・撤収時刻・会場・区画番号・残り日数）
- **出店ステータス**（申請中 → 審査中 → 確定 → 出店済み。キャンセルも保持）を進捗バーで表示
- **未払いアラート** — 未払いがあるときだけ最上部に赤帯で出し、金額・支払期限・残り日数を明示。期限を過ぎている場合は「超過」と表示します
- **支払い管理**
  - 請求書のダウンロード（PDF）
  - オンライン決済
  - 銀行振込報告フォーム（振込日・振込名義・実際の入金額）
  - 支払履歴一覧（入金日・方法・請求番号・金額）
  - 領収書発行
- **出店申請フォーム** — 開催回・出店区分・プラン（区画）・オプションを選ぶと、料金内訳と合計が入力中にその場で出ます

画面上部の「表示する出展者」を切り替えると、未払いのある出展者・審査中の出展者など、状態の違うマイページを確認できます。

## 【2】主催者の管理画面

募集文には出展者側の画面しか書かれていませんが、**出展者側だけでは運用が回りません。** 審査して確定にする人、入金を確認する人、当日の区画表を作る人がどこかに必要で、そこがExcelとメールのままだと「マイページの表示が実態と合っていない」状態が起きます。ステータスと入金状況を1か所で持たせるために、主催者側の画面をあわせて用意しました。

- 出展者一覧（出店日・出展者名・出店区分・プラン・区画・金額・ステータス・入金状況）
- **ステータスの一括変更**（審査中 → 確定 / 申請中 → 審査中）。確定にすると、その場で請求（未払い）が発行されます
- **未入金の絞り込み**（未払い・振込確認中）。開催回・ステータス・出店区分・フリーワードでも絞り込めます
- 振込報告の内容を一覧上で確認して「入金確認」、未払いへの「督促」
- **CSV書き出し**（BOM付きUTF-8。Excelでそのまま開けます）— 画面の絞り込み結果をそのまま書き出します

集計タイル（申込件数・請求合計・入金済み・未入金）は、**絞り込み後の表示中の行**を集計しています。絞り込みと数字がずれると使えないためです。

## 設定の差し替え方

出店区分・プラン・オプション・ステータス・料金は、すべて `index.html` の冒頭の設定オブジェクトにまとめてあります。**イベントごとに変わるのはここだけ**で、画面のコードは触りません。

```js
const EVENT = {
  name: "みなと河岸マルシェ",
  taxRate: 0.1,
  paymentDueDays: 10,      // 出店日の何日前を支払期限にするか
  bank: { ... },           // 振込先
  sessions: [              // 開催回。過去回も残すと支払履歴と実績がそのまま残ります
    { id: "s0829", date: "2026-08-29", open: "10:00", close: "16:00", setupFrom: "08:30", teardownBy: "17:00" },
  ],
};

const BOOTH_TYPES = [      // 出店区分と基本料
  { id: "cook", label: "飲食（調理あり）", baseFee: 15000, note: "保健所の臨時営業許可証と火気使用届の提出が必要です。" },
];

const PLANS = [            // プラン（区画）。基本料への加算
  { id: "std", label: "スタンダード区画", size: "3.0m × 1.5m", addFee: 4000 },
];

const OPTIONS = [          // 有料オプション
  { id: "power", label: "電源（〜1500W）", fee: 3000 },
];
```

- 料金は保存せず、**毎回この設定から計算**しています。単価を直せば、マイページ・申請フォーム・管理画面・CSVのすべてに同時に反映されます
- ステータス（`STATUSES`）と入金状況（`PAY_STATUSES`）も同じブロックで定義しています。名称・色・並び順の変更はここだけで済みます
- 実案件では、この部分をJSON / DBに外出しし、主催者が管理画面から編集できる形にします

## サーバー側で行う処理

デモは1ファイルで完結させているため、次の処理は画面の挙動だけを再現しています（画面上にも注記を出しています）。

| 処理 | 本番の構成 |
|---|---|
| 請求書・領収書のPDF生成 | サーバーで生成し、署名付きURLで配布 |
| オンライン決済 | 決済代行（Stripe等）の決済ページへ遷移。カード情報はアプリを経由しない |
| 入金の反映 | 決済完了をWebhookで受け取り、入金状況を自動更新 |
| 銀行振込の照合 | 振込報告を受けて事務局に通知。入金明細と突き合わせて消込 |
| 通知メール | 確定通知・支払期限のリマインド・督促 |

**React / Supabase / Vercel / Stripe** を想定した構成です。

## ダミーデータ

出展者6件（次回開催分）。うち**未入金2件**、**審査中1件**。ほかに申請中1件、振込確認中1件、入金済み1件。過去2回分の出店記録と入金履歴も入れてあり、支払履歴と実績の見え方を確認できます。

データはページを開くたびに初期状態に戻ります（`localStorage` は使っていません）。
