# 販売リスト自動生成

商品マスタ（商品名・仕入れ値・商品コード）と除外リスト（商品コード）から、**1コマンドで販売リストを生成**します。

- 除外リストに載っている商品を落とす
- 残った商品の販売価格を、設定ファイルのルールで計算する
- 販売リストのExcelと、処理サマリーを書き出す

**30万件で約29秒**（実測。内訳は下に出します）。販売価格の計算ルールはすべて `config.json` にあり、Pythonのコードは触りません。

## 30万件での実測処理時間

| 工程 | 秒 |
|---|---:|
| 商品マスタ30万行＋除外リスト5千行の読み込み（Excel） | 12.75 |
| 突合と販売価格の計算（29.5万行） | **0.70** |
| 販売リストのExcel書き出し（29.5万行・2シート） | 14.54 |
| 同じ内容のCSV書き出し | 1.21 |
| **合計** | **29.23** |

計測環境: Intel Xeon 2.80GHz / 4コア / メモリ16GB / Python 3.11 / pandas 3.0.5。**ピークメモリ 244MB**。
2回実行して 29.2秒 と 30.3秒。ブレは1秒程度です。

入出力の組み合わせを変えた場合も測りました。件数の結果はすべて同じ（出力 294,841件）です。

| 入力 | 出力 | 合計 |
|---|---|---:|
| Excel | Excel＋CSV | 29.2秒 |
| **CSV** | Excel | **14.5秒** |
| Excel | Excel（xlsxwriter が無く openpyxl で書いた場合） | 33.8秒 |

**時間のほとんどはExcelの読み書きです。** 肝心の突合と価格計算は0.7秒しかかかっていません。
毎日回すような運用で速度が問題になるなら、入力をCSVでいただくだけで15秒台になります。

> 再現するには `python make_samples.py --csv` でCSV版のサンプルも作り、`config.json` の
> `master.path` と `exclude.path` を `.csv` に差し替えてください。Excel／CSVは拡張子で自動判別します。

## VBAとの比較 — なぜこの件数でPythonを勧めるか

**VBAでも作れます。** ただし30万件では、書き方の制約がかなり強くなります。

VBAでこの処理を実用速度にするには、最低でも次が必須になります。

1. セルを1つずつ参照せず、`Range.Value` で**配列に一括で取り込む**
2. 除外リストの突合を `VLookup` / `Match` ではなく **`Scripting.Dictionary`** で行う
3. `Application.ScreenUpdating = False`、`Calculation = xlCalculationManual` を徹底する

これらを守れば、30万件でも「数分」の範囲には収まります。逆に、素直に書いた
（セル参照のループ ＋ `VLookup` で除外判定）実装だと、30万件 × 5千件の突合で処理が跳ね上がり、
待てない時間になります。**同じ「VBAで作る」でも、書き方で桁が変わる件数帯**ということです。

> ここで挙げたVBA側の時間は、同種処理の経験からの目安です。**実測値ではありません。**
> 実測してあるのは、このリポジトリのPython版（上の表）だけです。ご要望があれば、
> 同じサンプルデータでVBA版も実装して、同じ条件で計測してお出しします。

速度以外にも、この件数だと次の差が出ます。

| | VBA | Python（本デモ） |
|---|---|---|
| 30万件の処理 | 書き方次第。配列＋Dictionary必須 | **約29秒**（実測） |
| メモリ | Excelのプロセス内。32bit版Excelは約2GBが上限 | 別プロセスで244MB |
| 実行中のExcel | 操作できない（固まったように見える） | Excelは閉じたままでよい |
| 夜間・定時の自動実行 | Excelを起動した状態が必要 | タスクスケジューラで無人実行できる |
| 計算ルールの変更 | コードを直して再配布 | `config.json` を書き換えるだけ |
| 104万行を超えたとき | シート分割の実装が必要 | 自動でシートを分けて出力 |

**GASについて。** 希望スキルにGASとありましたが、数十万件では**Google Apps Scriptの実行時間制限（1回6分）**に
かかる可能性が高く、この件数の一括処理には向きません。スプレッドシート運用が前提なら、
「BigQueryに置く」「Pythonで処理して結果だけスプレッドシートに書き戻す」といった構成をご提案します。

### 操作は「Excelのボタン一つ」のままにできます

Pythonを勧めると「現場の人がコマンドを打つのか」という話になりますが、そこは変えません。

- **Excelにボタンを置き、VBAから裏でPythonを呼ぶ**（現場の操作は今までどおりボタン一つ）
- または `.bat` ファイルをダブルクリックするだけの形

つまり **UIはVBA、処理はPython** という分担が、この件数では一番素直です。
ご要望であれば全部VBAでもお作りします（その場合も上の1〜3を踏まえた実装にします）。

## 商品コードの表記ゆれを吸収する

**除外したい商品が除外されない事故は、ほぼ商品コードの表記ゆれで起きます。**
除外リストは人が手で作ることが多く、マスタとは別の系統で育つためです。

突合の前に、両方の商品コードを同じ形に揃えます（`generate.py` の `normalize_key`）。

| 設定 | 内容 | 例 |
|---|---|---|
| `nfkc` | 全角の英数字・記号・スペースを半角に寄せる | `ＡＢ－０００１２３` → `AB-000123` |
| `strip` | 前後の空白を落とす | `"AB-000123　"` → `AB-000123` |
| `strip_spaces` | 途中の空白も落とす | `AB- 000123` → `AB-000123` |
| `upper` | 大文字に揃える | `ab-000123` → `AB-000123` |
| `remove_chars` | 指定した記号を無視する（既定は無効） | `-` を指定すると `AB-000123` と `AB000123` が同一 |
| `digits_only` | 数字以外を落とす（既定は無効） | `AB-000123` → `000123` |

**元の表記は変えません。** 突合用の列を別に持つだけなので、出力される販売リストの商品コードは
マスタに入っていたままの表記です。

### 効果を実測しました

同梱サンプルは、除外リスト5,000件のうち約半分に表記ゆれを混ぜてあります（全角698・小文字634・前後空白516・途中空白377）。
吸収する／しないで比べると、こうなります。

```bash
python generate.py                          # 表記ゆれを吸収する
python generate.py config_ゆれ吸収なし.json   # 吸収しない
```

| | 除外できた件数 | 出力件数 |
|---|---:|---:|
| 吸収する（`config.json`） | **4,880** | 294,841 |
| 吸収しない（`config_ゆれ吸収なし.json`） | 2,655 | 297,065 |

**2,225件（45.6%）が除外されずに販売リストへ流れます。** しかも、そのまま出力されるので気づけません。
除外リストの4,880件は、5,000件から「マスタに無い120件」を引いた数と一致します。つまり取りこぼしゼロです。

### 気づけるようにする仕組み

表記ゆれを吸収しても、それだけでは事故は防ぎきれません。次の3つを毎回出します。

- **「除外リストにあるがマスタに無いコード」の件数** — 廃番なら正常ですが、この数が急に増えたら
  商品コードの採番ルールが変わった合図です（サンプルでは120件）
- **「除外一覧」シート** — 除外した商品を理由つきで出力します。除外が効いていることを目視で確認できます
- **「仕入れ値が読めない行」の件数** — 空欄や `－` で価格を計算できなかった行です。黙って0円にはしません

もうひとつ、**商品コードは必ず文字列として読み込みます。** 数値として読ませると `0012` が `12` になり、
長い数字コードは `1.0E+05` に化けます。除外漏れの典型的な原因です。

## 設定ファイルの書き方

`config.json` です。Pythonのコードは触りません。

```json
{
  "job_name": "販売リスト生成",

  "master": {
    "path": "samples/商品マスタ.xlsx",
    "sheet": 0,
    "columns": {
      "商品コード": "商品コード",
      "商品名": "商品名",
      "仕入れ値": "仕入れ値"
    }
  },

  "exclude": {
    "path": "samples/除外リスト.xlsx",
    "columns": { "商品コード": "除外コード" }
  },

  "code_rules": { "nfkc": true, "strip": true, "strip_spaces": true, "upper": true },
  "duplicate_codes": "first",

  "pricing": {
    "clean_cost": true,
    "tiers": [
      { "upto": 1000, "markup": 1.8 },
      { "upto": 5000, "markup": 1.6 },
      { "upto": null, "markup": 1.4 }
    ],
    "add": 0,
    "round": { "unit": 10, "mode": "ceil" },
    "min_price": 500
  },

  "output": {
    "path": "out/販売リスト_{日時}.xlsx",
    "csv": "out/販売リスト_{日時}.csv",
    "columns": ["商品コード", "商品名", "仕入れ値", "販売価格", "粗利", "粗利率"],
    "sort_by": "商品コード",
    "include_excluded_sheet": true
  },

  "summary": "out/生成サマリー.md"
}
```

### 入力

| 項目 | 内容 |
|---|---|
| `path` | ファイルの場所。`.xlsx` でも `.csv` でも同じように読みます |
| `sheet` | シート名またはシート番号（0始まり） |
| `header_row` | 見出しの行（0始まり。既定は0） |
| `columns` | **左が固定の名前、右がお使いのファイルの列名です。** 右側だけ書き換えてください |

例えば、お使いのマスタの列名が「品番」「品名」「原価」なら、こう書きます。

```json
"columns": { "商品コード": "品番", "商品名": "品名", "仕入れ値": "原価" }
```

### 販売価格の計算

上から順に適用します。

| 項目 | 内容 |
|---|---|
| `markup` | 掛け率。全商品一律ならこれだけで足ります（例: `1.5`） |
| `tiers` | 仕入れ値の帯ごとに掛け率を変える場合。`markup` の代わりに指定します |
| `tiers[].upto` | その帯の上限。**上限を含みます**（`1000` なら1000円まで）。最後の帯は `null` |
| `add` | 掛け率のあとに足す固定額（送料・手数料など）。例: `200` |
| `round.unit` | 端数処理の単位。`10` なら10円単位、`100` なら100円単位 |
| `round.mode` | `ceil`（切り上げ）／ `floor`（切り捨て）／ `round`（四捨五入） |
| `min_price` | 下限価格。端数処理のあと、これを下回る価格は引き上げます |
| `clean_cost` | `1,200円` `１２００` のような表記を数値として拾います（既定 `true`） |

同梱の設定では `仕入れ値 → 帯ごとの掛け率 → 10円単位で切り上げ → 500円を下回れば500円` になります。

```
仕入れ値   394円 → ×1.8 =   709.2 → 710円
仕入れ値 4,182円 → ×1.6 = 6,691.2 → 6,700円
仕入れ値   100円 → ×1.8 =   180.0 → 180円 → 下限500円
```

### 出力

| 項目 | 内容 |
|---|---|
| `path` | 出力先。`{日時}` は実行時刻に置き換わります（既定の書式は `20260816_1411`） |
| `timestamp_format` | `{日時}` の書式。`"%Y-%m-%d"` のように指定できます |
| `csv` | 指定するとCSVも同時に出します。省略すると出しません |
| `columns` | 出力する項目と並び順。`商品コード` `商品名` `仕入れ値` `販売価格` `掛け率` `粗利` `粗利率` から選びます |
| `sort_by` | 並べ替えに使う項目 |
| `include_excluded_sheet` | 除外した商品を「除外一覧」シートに理由つきで出します（既定 `true`） |
| `engine` | `xlsxwriter`（速い・既定）／ `openpyxl`。`auto` なら使えるほうを選びます |
| `duplicate_codes` | `first` なら同じ商品コードの2行目以降を落とします。`keep` なら残します |

出力されるもの。

```
out/
  販売リスト_20260816_1411.xlsx    販売リスト＋除外一覧の2シート
  販売リスト_20260816_1411.csv     同じ内容（csv を指定した場合）
  生成サマリー.md                   件数と処理時間
```

Excelの上限（1シート約104万行）を超える場合は、`販売リスト_1` `販売リスト_2` と自動でシートを分けます。

## 数十万件で破綻させないためにしていること

| | 内容 |
|---|---|
| 行ループを書かない | 突合も価格計算もpandasで一括処理します。30万件でも0.7秒です |
| 必要な列だけ読む | 商品マスタから使う3列だけに絞ってから処理します |
| 書き出しを溜めない | `constant_memory` で1行ずつ吐き出します。件数が増えてもメモリが膨らみません |
| 失敗した行だけ再処理 | 仕入れ値の表記ゆれ処理は、数値として読めなかった行にだけかけます |
| 除外の突合はハッシュで | `isin` による集合判定です。件数が増えても線形にしか増えません |

30万件でピークメモリ244MB。100万件でも1GB弱の見込みです。

## ファイル構成

```
demos/hanbai-list/
  generate.py                  販売リストを生成する本体
  make_samples.py              サンプルExcelを作る（30万件）
  config.json                  設定ファイル
  config_ゆれ吸収なし.json       表記ゆれを吸収しない比較用
  README.md
```

`samples/` と `out/` は実行時に作られます（バイナリのためリポジトリには入れていません）。

商品コードの正規化は、同じリポジトリの `excel-kit/run.py` の `normalize_key` と同じ考え方です。
突合が失敗する原因のほとんどがここなので、どのツールでも最初に入れています。
