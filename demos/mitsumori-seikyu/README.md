# 見積書・請求書の作成 デモ

`index.html` をブラウザで開くだけで動きます。インストール・ビルド不要、1ファイル完結です。意匠は索引ページ（リポジトリ直下の `index.html`）と共通で、冒頭から索引ページに戻れます。

**商品マスタ → 見積書 → 請求書 → 発行・入金の消し込み** という流れを、実際にボタンを押しながら確認できます。

---

## この画面が言いたいこと：単価の間違いも発行漏れも、マスタがないから起きる

「前回のファイルをコピーして書き換えている」「単価の間違いが起きる」「発行漏れがある」。この3つは別々の症状に見えますが、原因は1つです。**単価と帳票の状態を持つ場所がなく、都度ファイルを複製しているためです。**

- 単価がファイルの数だけ存在する　→　どれが正しいか分からなくなる
- 帳票が個人のフォルダにある　　　→　出したかどうかが分からない
- 出したあとを追う場所がない　　　→　入金されていないことに気づかない

この画面では、単価をマスタの1か所に置き、帳票の状態（未発行・発行済・入金済・期日超過）を1つの一覧で持つと、上の3つが同時に消えることを示しています。

---

## 【1】商品マスタ

商品12件を、品番・品名・単位・単価・税区分で持っています。**単価と税区分は画面上で直せます。**

直した値は、これから作る帳票に使われます。すでに発行した帳票の金額は変わりません（発行時点の単価を帳票側が持っているためです）。価格改定のときに直すのは、この表の1行だけです。

取引先5社は、支払条件（月末締め・翌月末払いなど）をあわせて持っています。請求書の支払期日は、この条件から自動で決まります。

## 【2】発行状況の一覧 — ここが中心です

見積書と請求書を1つの表にまとめ、状態で分けています。

| 区分 | 何を表すか | 色 |
|---|---|---|
| 未発行 | 作ったまま出していない帳票。**発行漏れの候補** | 臙脂 |
| 発行済・入金待ち | 出してあり、支払期日がまだ来ていない | 紺 |
| 期日超過 | 期日を過ぎて入金がない。**回収漏れ** | 臙脂 |
| 入金済 | 消し込みが済んだもの | 紺 |
| 見積のまま | 見積書は出したのに、請求書に進んでいない | 臙脂 |

**期日超過は人が印を付けるものではありません。** 支払期日と基準日を比べて自動で付き、何日超過しているかも出ます。催促の順番は、この日数で決められます。

行の「発行する」「入金を消し込む」を押すと、その場で状態が変わり、上の集計金額も変わります。「内訳」を押すと明細と税率ごとの内訳が開きます。

## 【3】見積書の作成

マスタから商品を選び、数量を入れるだけです。**単価は入力しません。** 小計・消費税・合計は入力のたびに計算しなおします。見積番号は、いま持っている番号の次を自動で割り当てます（番号の重複と抜けが起きません）。値引きの行も追加できます。

## 【4】見積書から請求書へ

見積書を選んで1回押すだけで、請求書になります。**金額を入力しなおす場面はありません。**

- 引き継ぐもの：品名・数量・単価・単位・税区分・値引き（全行）
- 新しく決まるもの：請求番号・発行日・支払期日（取引先の支払条件から自動）

変換前と変換後の合計を並べて表示しているので、金額が変わっていないことをその場で確認できます。変換した見積書は「請求へ変換済」になり、「見積のまま」の数から外れます。

## 【5】インボイス対応

適格請求書の記載事項6項目が、帳票のどこに出ているかを対応表で示しています。

1. 発行者の名称および登録番号／2. 取引年月日／3. 取引の内容（軽減税率の対象品目である旨）／4. 税率ごとに区分して合計した対価の額および適用税率／5. 税率ごとに区分した消費税額／6. 交付を受ける事業者の名称

**端数処理は切り捨て・四捨五入・切り上げを画面上で切り替えられます。** 切り替えると、帳票と一覧の金額がその場で変わります。「税率をかけた値（小数のまま）」「処理の方法」「消費税額」「端数処理による差」を並べているので、どこで端数が動いたかが見えます。

端数処理は、1枚の帳票につき**税率ごとに1回だけ**行っています。行ごとに端数処理をすると、適格請求書として認められる方法から外れます。

## 【6】手作業との比較

月間の発行件数と1件あたりの分数を入れると、削減できる時間と年間の人件費換算が出ます。初期値は月40件・1件12分です。

## サンプルデータ

すべて架空です。取引先5社・商品12件・帳票15件（見積書6件／請求書9件）。次のものを必ず含めています。

- **期日を過ぎている未入金**：3件（13日超過・28日超過・38日超過）
- **見積のまま請求に進んでいないもの**：3件（うち1件は有効期限も切れています）
- **軽減税率8%の行と標準税率10%の行が混在する伝票**：複数件
- **値引きが入った伝票**：2件（見-2026-0011、請-2026-0008）

請-2026-0008 は、混在と値引きの両方が入っています。標準税率の対象額が 44,465円 のため、消費税が 4,446.5円 になり、端数処理の方法で金額が変わります。インボイス対応の画面の初期表示にしてあるのはこの請求書です。

## 設定の差し替え

ファイル冒頭の設定を書き換えるだけで、別の会社・別の商品構成の帳票になります。コード本体は品名や単価を直接持っていません。

| 設定 | 内容 |
|---|---|
| `BASE_DATE` | 基準日。期日超過の判定に使います（実装時はその日の日付） |
| `COMPANY` | 自社の名称・住所・**登録番号**・振込先 |
| `TAX_CONFIG` | 税率の定義（標準10%・軽減8%）、端数処理の方法、端数処理の単位 |
| `QUOTE_VALID_DAYS` | 見積書の有効期限（発行日からの日数） |
| `NUMBERING` | 帳票番号の採番規則（接頭辞と桁数） |
| `ITEM_MASTER` | 商品マスタ。品番・品名・単位・単価・税区分 |
| `CLIENTS` | 取引先マスタ。名称・住所・支払条件（締めと支払日） |
| `DOC_SEED` | 帳票の初期データ |
| `MANUAL` | 手作業との比較の初期値 |
| `INVOICE_REQUIREMENTS` | 適格請求書の記載事項と、帳票での記載箇所 |

税率が変わったときに直すのは `TAX_CONFIG` の1か所です。

## 数値の扱い

会社名・商品名・金額・日付は、**すべてデモ用の架空のもの**です。実在する企業・取引とは関係ありません。削減時間も、入力した条件から計算した想定値です。

画面上の操作内容はブラウザの中だけに保持され、どこにも保存・送信されません（localStorage・Cookie・外部通信のいずれも使っていません）。ページを開き直すと最初の状態に戻ります。

**税制の取扱い（端数処理の方法、軽減税率の対象、値引きや返品の扱いなど）は、顧問税理士に確認していただくことを前提としています。** こちらで税務上の判断を行うことはありません。決まった扱いを、そのとおりに帳票へ反映する部分を作ります。

## 実装時の構成

本デモは画面確認用のため、データはファイルに埋め込んでいます。実際にお渡しするものは、お手元のExcelや会計ソフトの様式に合わせた形になります。いまお使いの帳票の見た目を変えずに、中身の作り方だけを変えることもできます。

実装時は次の部分が加わります。

- **帳票の書き出し** — PDFまたはExcelとして出力。既存の様式をそのまま使えます
- **マスタと帳票の保存** — 商品・取引先・発行済の帳票を1か所に持ちます
- **期日超過の通知** — 期日を過ぎた請求書を、その日に知らせます
- **会計ソフトへの連携** — 使用中のソフトの取り込み形式に合わせて出力します

はじめにお預かりするものは、いまお使いの見積書・請求書のファイル1枚と、商品の一覧（品名・単価・単位・税区分）です。この2つがあれば、マスタの形を決められます。

**デモは React / Tailwind CSS（1ファイル構成・CDN読み込み・ビルド不要）／実装時は運用に合わせて、Excel＋Pythonまたは Web アプリの構成**
