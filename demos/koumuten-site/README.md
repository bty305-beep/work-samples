# 工務店コーポレートサイト（デモ）

`index.html` をブラウザで開くだけで動きます。ビルド・インストールは不要です。

新築・リフォームの**問い合わせ獲得**を目的にした、工務店サイトの全6ページ構成です。
画面右上の「設計意図をひらく」から、各ページで何を狙って組んでいるかを確認できます。

---

## ページ構成（全6ページ）

| # | ページ | 内容 |
|---|---|---|
| 1 | トップ | ファーストビュー、対応エリア、選ばれる理由、施工事例の抜粋、問い合わせ導線 |
| 2 | 施工事例一覧 | 新築 / リフォーム・エリアでの絞り込み |
| 3 | 施工事例の詳細 | Before/After、費用の内訳、工期、お客様の声、事例ページ専用の問い合わせ枠 |
| 4 | リフォームのご案内 | 部位別（キッチン・浴室・外壁・トイレ・内装・断熱）の費用と工期 |
| 5 | 会社案内 | 代表挨拶、沿革、有資格者、会社概要、対応エリア |
| 6 | お問い合わせ | 必須チェックと入力形式の検証つきフォーム |

## 問い合わせを取るための設計

工務店サイトで問い合わせが発生するのは、トップページではなく**施工事例の詳細ページ**です。
自分の家に条件の近い事例（築年数・家族構成・エリア）を1件見つけて、詳細まで読んだ人が動きます。
そのため、この構成は次の4点を軸にしています。

**1. 事例詳細を最重要ページとして扱う**
トップ・一覧・リフォーム案内・関連事例のすべてを、事例詳細への導線として設計しています。

**2. 事例詳細に費用の目安と工期を必ず載せる**
金額を書かないサイトは「聞かないと分からない＝営業をかけられる」と受け取られ、そこで離脱します。
総額だけでなく内訳・追加費用が発生する条件・補助金まで書くことで、あとで金額が動く不安を先に潰します。
書くほど問い合わせ件数は絞られますが、**予算感の合った問い合わせだけが残る**ため受注率は上がります。

**3. 電話とフォームを両方、常時表示する**
工務店の客層は電話が多く、特に50代以上のリフォーム層はフォーム入力を嫌います。
一方、日中に電話できない共働き層はフォームを使います。どちらかに寄せると片方を丸ごと落とします。
PCはヘッダー固定、スマホは画面下固定。電話は `tel:` リンクでワンタップ発信し、受付時間も併記しています。

**4. 対応エリアを早い段階で明示する**
エリア外からの問い合わせは、対応もお断りの連絡も工務店側の負担になります。
ファーストビュー直下・フッター・フォームの3箇所に明示し、フォームでは市区町村を選択式にして
エリア外を選ぶとその場で注意を表示します（送信自体は止めません。紹介できる場合があるためです）。

公開後は「事例詳細ページの閲覧数」と「そこからの問い合わせ数」を対にして見ます。
どの事例が問い合わせを生んでいるかが分かれば、次に撮る写真と次に載せる事例が決まります。

## 設定オブジェクトで他社にも転用できます

会社名・配色・対応エリア・施工事例・リフォームメニュー・沿革・フォームの選択肢は、
すべてファイル冒頭の `SITE` オブジェクトに集約しています。コードには一切べた書きしていません。

```js
const SITE = {
  company: { name: "宮下工務店", tel: "0120-48-7200", ... },
  theme:   { primary: "#1F4B3F", accent: "#C0703A", ... },  // 配色はCSS変数に流し込み
  areas:   { primary: ["△△市", "◯◯市", ...], ... },        // フォームの選択肢とエリア外判定に共用
  works:   [ { id, type, title, area, age, family, price, term, tags, summary }, ... ],
  reformMenus: [ ... ], history: [ ... ], qualifications: [ ... ],
};
```

- **配色**は `theme` の4色を変えるだけでサイト全体が変わります（CSS変数経由）
- **対応エリア**は `areas` の1箇所を直せば、トップ・フッター・フォームの3箇所とエリア外判定に反映されます
- **施工事例**は配列に追加するだけで、一覧・絞り込み・関連事例・トップの抜粋にすべて反映されます

WordPress で実装する場合は、この構造をそのままカスタム投稿タイプ + カスタムフィールドに対応させます。

| このデモの構造 | WordPress側 |
|---|---|
| `works[]` | カスタム投稿タイプ `works`（費用・工期・エリア・築年数・種別をカスタムフィールド化） |
| `works[].type` / `.area` | タクソノミー（新築 / リフォーム、市区町村）→ 一覧の絞り込みに使用 |
| `reformMenus[]` | 固定ページ + 繰り返しフィールド |
| `company` / `areas` / `theme` | テーマオプション（1箇所直せば全ページに反映） |
| お問い合わせフォーム | Contact Form 7 / Snow Monkey Forms + 自動返信・管理者通知 |

2件目以降の工務店案件では、構成の検討からではなく**データの差し替えから始められます**。

## 技術構成

- React 18 + Babel Standalone + Tailwind CSS（すべてCDN、1ファイル完結）
- localStorage 不使用。ページを閉じると入力内容は残りません
- フォームは送信内容をどこにも保存・送信しません（入力チェックのみ動作します）

実案件は WordPress（オリジナルテーマ）での構築を想定しています。

※ 社名・実績・写真・お客様の声はすべて架空のものです。写真は色付きの枠で代用しています。
