# シフト作成の自動化 デモ

`index.html` をブラウザで開くだけで動きます。インストール・ビルド不要、1ファイル完結です。意匠は索引ページ（リポジトリ直下の `index.html`）と共通で、冒頭から索引ページに戻れます。

制約を設定する → 希望を取り込む → 自動生成する → **満たせなかった制約を見る** → 手直しする、という流れを、実際に操作しながら確認できます。

---

## この画面が言いたいこと：組む作業は機械、判断は人

シフト作成に半日かかるのは、字を書くのが遅いからではありません。**必要人数・資格・連勤・希望という制約条件を、人が頭の中で解いているから**です。条件が1つ変わるたびに、解き直しが発生します。

組み合わせを探す作業に、人の判断は要りません。判断が要るのは「**どの条件を、今回だけ、誰に頼んで緩めるか**」のほうです。

**この画面の中心は、組み上がったシフト表ではなく、満たせなかった制約の一覧です。** 完全な自動化は謳いません。人が見るべき場所を絞るための道具として作っています。

---

## 画面の構成

### 【1】制約の設定

頭の中にある条件を、数字にして置いておく場所です。画面上で増減できます。

| 設定できるもの | 初期値 |
|---|---|
| 各時帯の必要人数（平日） | 朝番2名／昼番2名／夕番2名 |
| 各時帯の必要人数（土日） | 朝番3名／昼番3名／夕番2名 |
| 各時帯の有資格者の必須人数 | 全時帯に1名 |
| 連勤の上限 | 5日 |
| 連休の保証 | 期間中に最低1回、2日連続 |

変更後に［この条件で自動生成する］を押すまでは、前の条件の結果を表示したままにしています。押すまで結果が変わらないことを画面上に明記しています。

条件が人の頭の中にしかないと、その人が休んだ月にシフトが組めません。数字にした時点で、引き継ぎができる形になります。

### 【2】希望の取り込み

スタッフ12名 × 14日の一覧に、出勤希望と出勤不可を並べています。紙やチャットで集めた内容がここに入ります。ここまでが人の作業、ここから先が機械の作業です。

### 【3】自動生成

押した瞬間に組み上がります。組むときに守る順番を画面上に明示しています。

1. **出勤不可の日・1日1コマ・週の勤務回数の上限** — どんな場合も破りません
2. 有資格者の必須人数
3. 各時帯の必要人数
4. 連勤の上限と連休の保証
5. 出勤希望

人数が足りなくなるときに限って連勤の上限を超えることがあり、**超えた分は【4】にそのまま出します。黙って条件を緩めることはしません。**

あわせて、**組み方では解消できない不足**を切り分けて表示します。初期データでは、有資格者が要るコマが期間中42コマあるのに対し、在籍3名を勤務可能な日いっぱいまで入れても28コマが上限で、**差の14コマは誰をどこに置いても埋まりません**。これは配置の問題ではなく、採用・資格取得・営業時間の見直しという経営判断の材料です。手で組んでいると、この「そもそも足りない」が半日かけた後に分かります。

### 【4】満たせなかった制約 ← ここが中心

種類ごとにまとめ、件数と場所を臙脂で出します。初期状態では24件です。

| 種類 | 件数 | 表示の例 |
|---|---|---|
| 人数が足りない時帯 | 5件 | 9月9日（水）朝番　1名不足（必要2名／配置1名） |
| 登録販売者がいない時帯 | 14件 | 9月6日（日）夕番　登録販売者が1名不足（必要1名／配置0名） |
| 連勤の上限を超えた人 | 1件 | 佐藤 直人　6連勤（上限5日）　8月31日から9月5日まで |
| 連休が取れていない人 | 1件 | 佐藤 直人　続けて休めるのが最長1日（保証したいのは2日連続） |
| 出勤希望に応えられなかった分 | 3件 | 伊藤 誠　9月12日（土）　計1件 |
| 週の勤務回数の上限を超えた人 | 0件 | （手直しで契約を超えたときだけ出ます） |

各グループには「**なぜ人が見る必要があるのか／何を判断すればよいか**」を1文添えています。件数を並べるだけでは、次にすることが決まらないためです。

**守られている条件**も紺色で併記しています。表を見て確かめる必要がない範囲を示すためです。人が見るのは臙脂の部分だけで足ります。

### 【5】シフト表と手直し

12名 × 14日のシフト表です。スマホ幅では横スクロールし、氏名の列は左端に固定されます。

- **ますを押すと、その人のその日の勤務を変えられます。** 変えた瞬間に【4】の一覧と表の判定が更新されます
- **出勤不可の日と、入れない時帯のボタンは押せません。** 理由（出勤不可の申告／学生のため平日の昼間は不可／夕番は不可）を操作盤に表示します
- 表の下部に「配置／必要」の集計行を時帯ごとに置き、不足しているますを臙脂にします。有資格者が0名の時帯には「資格0」と併記します
- 氏名の下に、その人に出ている違反（6連勤／連休なし／週の上限超過）を表示します
- 手直しで契約上の週の回数を超えると、その場で新しい違反として出ます

### 【6】手作業との比較

スタッフ人数・1回にかかる時間・月に組む回数を入れると、削減時間の目安が出ます。

自動化後の1回 ＝ **通しの確認15分 ＋ 1人あたり1分 × 人数 ＋ 満たせなかった制約1件あたり3分 × 件数**

組み上げ自体の時間は入れていません。押した瞬間に終わるためです。初期値（12名・240分・月3回）では **月7.1時間・年84.6時間** の削減になります。

**満たせない制約が多いほど、確認と手直しの時間は増えます。** 制約の置き方そのものが作業時間に効いてくるため、【1】の設定を変えるとこの数字も動きます。

## サンプルデータ

薬粧店1店舗、スタッフ12名、2週間（8月31日 月曜 〜 9月13日 日曜）。**すべて架空のデータです。**

- **有資格者（登録販売者）は3名だけ** — 田村（正社員・週5）／佐藤（正社員・週6）／小林（パート・週3・夕番不可）。全時帯に1名必要という制約に対し、構造的に14コマ足りません
- **誰も入れない日** — 9月9日（水）は12名中8名が出勤不可（全店合同の研修日という設定）。残る4名のうち3名は入れる時帯が限られており、朝番と昼番が埋まりません
- **希望が集中する日** — 出勤希望は期間全体で24件。9月12日（土）に5名が集中します
- **学生4名は平日の昼間（朝番・昼番）に入れません** — 平日は夕番のみ、土日は全時帯
- **フルタイムとパートの混在** — 正社員4名（週5〜6回）／パート4名（週3〜4回）／学生4名（週2〜3回）。パート3名は夕番不可、1名は朝番不可

**完璧には埋まりません。** 必要92コマに対し、全員を契約上限まで入れた場合の配置可能数がちょうど92コマで、余力ゼロだからです。数のうえでは足りていても、入れる時帯が人によって決まっているため、実際には86コマしか埋まりません。全部埋まるデータでは、制約違反の表示が意味を持たないためこうしています。

## 設定を変えると結果が変わることの確認

| 操作 | 満たせなかった制約 |
|---|---|
| 初期状態 | 24件 |
| 昼番の登録販売者を1名 → 0名にして再生成 | **11件** |
| 連勤の上限を5日 → 4日にして再生成 | 25件（連勤超過が2件に増える） |
| 連休の保証を2日 → 3日にして再生成 | 28件（連休なしが5件に増える） |
| 夕番の平日の必要人数を2名 → 3名にして再生成 | 31件 |

## 設定の差し替え

条件はファイル冒頭の設定オブジェクトにまとめています。**コード本体を触らずに他業種へ転用できます。**

| 設定 | 内容 |
|---|---|
| `ORG` | 事業所名・対象・期間の表示 |
| `QUAL` | 資格の呼び名（初期値は「登録販売者」） |
| `SLOTS` | 時帯の定義。ID・名称・時間帯・平日/土日の必要人数・有資格者の必須人数 |
| `RULES` | 連勤の上限、保証する連休の日数 |
| `DAYS` | 対象期間の日付と曜日 |
| `STAFF` | スタッフ名簿。区分・資格の有無・週の上限・常時不可の時帯・学生かどうか・出勤不可日・出勤希望日 |
| `NG_REASON` | 出勤不可が集中した日の理由（注記に表示） |
| `COMPARE` | 手作業との比較の初期値と、確認時間の見積り式 |

差し替えの例。時帯の定義と資格の呼び名を変えるだけで、画面のつくりと判定の仕組みはそのまま使えます。

| 業種 | `SLOTS` | `QUAL` |
|---|---|---|
| 介護事業所 | 早番／日勤／遅番 | 介護福祉士 |
| 飲食店 | 仕込み／ランチ／ディナー | 食品衛生責任者 |
| 警備 | 日勤／夜勤 | 警備員指導教育責任者 |

## 数値とデータの扱い

スタッフの氏名・勤務条件・出勤希望・削減時間は、**すべてデモ用の架空のデータ**です。実在する企業・人物・実績とは関係ありません。削減時間は**想定値**であり、1件あたりの確認時間は現場によって変わります。導入を検討する際は、実際に1か月ぶんを並行して回し、実測に置き換えてください。

画面上の操作内容はブラウザの中だけに保持され、どこにも保存・送信されません（localStorage・Cookie・外部通信のいずれも使っていません）。ページを開き直すと最初の状態に戻ります。

**このデモが扱う制約は、必要人数・有資格者・連勤・連休だけです。** 実際の運用では、労働基準法上の休憩の付与、連続勤務や法定休日の扱い、時間外労働の上限などを満たす必要があります。設定値は自社の就業規則と実態に合わせて調整してください。この画面はその判断を代替するものではありません。

## 生成の仕組み

条件の少ない時帯から順に埋める、点数付けの貪欲法です。1日ずつ、その日いちばん埋めにくい時帯から処理します。

候補者の点数は、出勤希望・契約回数の消化の遅れ・週内での配分・連勤の状態から決めます。有資格者は資格が必要な枠に残すため、そうでない枠では点数を下げています。同点は名簿順で決まるため、**同じ条件なら常に同じ結果**になります。

判定は生成とは独立した関数で行い、自動生成の直後でも手直しの後でも同じ処理を通します。表示されている違反が、いま画面にあるシフト表そのものの判定であることを保証するためです。

実装時は、希望の提出をスタッフのスマートフォンから受け、生成と判定をサーバー側に置きます。規模が大きい場合や制約の種類が増える場合は、貪欲法ではなく整数計画法（制約ソルバー）に置き換えます。確定したシフトの配信、勤怠実績との突き合わせ、労働時間の集計まで含めて1本につながります。

**デモは React / Tailwind CSS（1ファイル構成・CDN読み込み・ビルド不要）／実装時は React・Next.js・Supabase 構成**
